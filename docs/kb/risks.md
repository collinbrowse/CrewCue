# Risk register

Triaged risks, each tied to code or a doc. Mechanical signals (unguarded routes, large files, timers, parity gaps) are in [generated/risk-signals.md](generated/risk-signals.md); this page decides which of them matter. Severity is impact on a runner or crew on race day, or on user data.

IDs are stable. Closed risks move to the bottom with the change that closed them.

## Public on purpose

Routes the generator flags as unguarded that are meant to be public. Re-check if one changes.

- `GET /health/live`, `GET /health/ready`: Railway health checks.
- `GET /race-rooms/join-preview/:roomCode`: pre-join preview, see R8.
- `GET /strava/oauth/redirect`: Strava's browser redirect; it only bounces to the app deep link. The state is checked at the authenticated callback.
- `GET /chat/photos/*`: dev photo reads, served only by the in-memory store and only with a valid signed `exp`/`sig`; with a bucket it answers 404 ([chatRoutes.ts](../../services/api/src/routes/chatRoutes.ts:372)).

Flagged but guarded where the generator cannot see: `POST /chat/devices` and `POST /chat/push/tokens` share a handler that returns 401 without `request.identity` ([chatRoutes.ts](../../services/api/src/routes/chatRoutes.ts:384)). `POST /billing/revenuecat` and `POST /billing/admin/comp` take no JWT. Each one checks a server secret with a constant-time compare and returns 401 on a mismatch; the webhook returns 503 when its secret is unset ([billingRoutes.ts](../../services/api/src/routes/billingRoutes.ts:31), [billingRoutes.ts](../../services/api/src/routes/billingRoutes.ts:92), [billingRoutes.ts](../../services/api/src/routes/billingRoutes.ts:198)).
